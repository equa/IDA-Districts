about=Districts Modeler is a free QGIS plugin developed by EQUA for creating, managing and preparing map-based models of district energy systems for simulation with IDA Districts, EQUA’s district energy simulation software. Districts Modeler and IDA Districts are products of EQUA. The plugin is free to use; detailed dynamic simulation is carried out in IDA Districts.
 
 The Districts Modeler helps users build digital representations of district heating, district cooling and low-temperature energy networks by combining buildings, pipes, substations, energy plants, storage systems and consumers in one GIS-based environment. The plugin makes it easier to understand how a thermal energy network is structured, how different components are connected and how system data can be prepared for further analysis. Districts Modeler supports the preparation of consistent, simulation-ready models by providing tools for spatial data processing, network topology generation, data management, validation and visualisation directly in QGIS. Model data is stored in a PostgreSQL/PostGIS database and can be exchanged with IDA Districts for detailed dynamic simulation. 
 
 The physical simulation itself is performed in IDA Districts, where users can analyse thermal and hydraulic network behaviour, building energy demand, energy sources, storage systems, control strategies and system performance over time.
 
 Typical applications include district heating and cooling planning, network modelling, transformation studies, analysis of existing infrastructure, preparation of low-temperature or bidirectional network concepts, integration of renewable energy sources and support for research and planning projects.
 
 Districts Modeler is intended for engineers, utilities, planners, municipalities, researchers and other stakeholders who want to prepare transparent and simulation-ready district energy models for use with IDA Districts.

changelog=2.0.0.0
 - Cost optimization: pipe sizes with the least net present value (cost model over all simulated hours, comfort penalties, protected lines, required loads), HTML report of the iterations
 - Network built in stages: table of stage versions with their start years, sizing coupled over all stages, NPV by stage years
 - Sensitivity analysis of the cost optimization: parameter table, variant designs, estimate per variant, interactive plots (parallel coordinates, flips), full variants as own runs, validation of an estimate by simulation
 - Cost data and economic evaluation of a version: pipe and trench costs, economic scenarios, electricity price profiles, priced pipe losses
 - Energy use of plants and customers (boilers, heat pumps, heat exchangers): energy costs per carrier in the NPV
 - Representative periods: three weeks from the climate file of the version, simulated in parallel, weighted to a full year
 - Hydraulic balancing (formerly dynamic pipe sizing): supply/return pairs each balanced as its own circuit, calculation and start-up period, reference run, inner diameter per iteration on the map, own icon
 - Requested outputs: power of the network pumps and room setpoints
 - Zeta values of the junctions calculated from textbook values (option in pipe laying, network topology and pipe sizing)
 - Junction heights taken from the connected lines
 - Pipe series catalogue with product data (incl. flexible isoplus pipes) and mechanical material properties for the pipe statics
 - Statics model: mechanical network model of a version (route nodes, sections, bends by rule) for the pipe statics
 - AI connection: read-only MCP tools for Claude Desktop and Claude Code (opt-in), and an AI assistant tab in the Districts Modeler (per-project permission)
 - Info texts in the pipe laying, network topology and pipe sizing dialogs; messages translated (German)
 - Faster: build network model (999 substations: over 10 min to 8 s), load results (about 3x), show data on map (2-3x)
 - Project import/export independent of the exporting server (encoding, owner)
 - Debug output into a rotating log file instead of editing the source files
 - Fixes: every simulation after the first one in a QGIS session failed; results of bundles with a varying number of pipes stored in the wrong tables; pipe sizing truncated networks that were not sized; Kusuda ground parameters in leap years; boreholes without a point; Save of pipe laying and topology only after a finished run; new project without psql errors; feature model parameter mapping ids
 - Tested on QGIS 3.44 and 4.2
