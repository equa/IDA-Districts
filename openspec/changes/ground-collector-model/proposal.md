## Why

The Districts Modeler has no horizontal ground heat exchangers: ring trench collectors (horizontal or vertical
rings), flat collectors and bare pipes that use the ground as a heat store. Today a route's pipe sees the ground only
as a fixed boundary (`TGround` of the Climate macro), without storage, recovery or freezing, and vertical boreholes
exist only inside an energy plant. The explore session of 2026-11-20 (decisions T1–T15) designed collectors as routes
of the network with one Modelica model for all collector types, set only by geometry. Its ground is an RC network whose
values the plugin fits to a coarse 2D cross-section.

The work is split into two changes. This first one builds everything that does not need IDA Districts: the parameter
contract of the Modelica components, the geometry description, the 2D reference, the fit and a Python model of the
ground. The Modelica model is developed against them in the IDA Districts library. The second change
(`ground-collector-routes`) brings collectors into the routes, the resources tab, the model build, the costs and the
results once that model exists.

## What Changes

- Parameter contract (with a version number) of two Modelica components for the IDA Districts library:
  `GroundCollector` (plug-flow loop pipe × n loops, M ground sections with a fixed structure of four RC nodes, latent
  heat in the coil region and around it) and `GroundSurface` (surface energy balance: convection, absorbed global radiation, long-wave
  exchange with the sky; heat port to the ground).
- Generic collector geometry per trench meter (source region width × height at a depth, loop length per trench
  meter, loop pipe, trench spacing) with presets for horizontal ring, vertical ring, flat meander and bare pipe that
  fill it from the type-specific inputs.
- 2D reference: a coarse finite-volume cross-section (half the trench spacing wide, symmetry on both sides) with
  freezing (apparent heat capacity) and the same surface balance as `GroundSurface`.
- Automatic fit of the RC values to the heat flow into the fluid of the 2D reference, with the collector's surface
  linearized, per collector description; error measure, acceptance and a fingerprint of its inputs (geometry, soil,
  surface).
- Python ground model (RC ground, freezing, surface; no pipe), with the same equations as the contract. It computes
  the pre-calculated start state (k years with a fixed mean fluid temperature). Sky temperature and sun elevation
  from the climate file with the equations of IDA's `ENVIRONMENT` model, so the start state sees the simulation's sky.
- Validation cases at the pipe wall on a real climate year (Kalmar; inputs and the results of the Python ground model
  and the 2D reference with the full surface balance) for the Modelica ground part; analytic test cases for the
  Modelica pipe (delay, constant wall temperature, energy balance).
- Pure functions: no database, no UI, no simulation. Nothing changes for the user yet.

## Capabilities

### New Capabilities
- `ground-collector-model`: contract, geometry and presets, 2D reference, RC fit, Python ground model with start state, and
  validation cases of the ground collector model.

### Modified Capabilities
None.

## Impact

- Code: new pure-function modules in `districts/utility_functions/` (geometry and presets, contract, 2D reference,
  climate signals, fit and ground model); numpy and scipy, which both QGIS versions ship (already used by `pipe_sizing.py`).
- Test data: validation cases in `districts/test/data/ground_collector_cases/` (about 1.7 MB, gzip), generated by a
  script in `districts/test/` from IDA's KALMAR.PRN; `districts/test/data/ground_climate_ida.csv` (KALMAR excerpt with
  IDA's sky temperature).
- Tests in `districts/test`, mypy baseline unchanged (new modules type-checked clean).
- README.md, CLAUDE.md.
- No change to the DB schema, the UI, the translations, the model build or the simulation.
